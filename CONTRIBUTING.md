# Contributing

## Before you start

- For a bug, open an issue with steps to reproduce.
- For a feature or a larger change, open an issue first and describe the use case. A short discussion saves a rejected pull request.
- Small fixes, such as typos, docs or an obvious bug, can go straight to a pull request.

Each repository has a README with its build and test commands.

## Rules

- No AI-generated images or other assets. Algorithms are deterministic: the same input gives the same output.
- New dependencies use one of these licenses: MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, Zlib, Unicode-3.0, CC0-1.0. No GPL, LGPL or AGPL.
- Write code, comments, commits and docs in English. Use only the ASCII hyphen `-`, not em or en dashes.
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`, `test:`, `chore:`.
- One logical change per pull request. CI must be green before a merge.

Follow the [code of conduct](CODE_OF_CONDUCT.md). Report security problems as described in the [security policy](SECURITY.md), not in public issues.
